## 1. 产品概述

### 1.1 一句话描述

AI 驱动的跨境贸易情报 SaaS —— 不再靠运气找买家，系统每日自动推送精准买家情报。

### 1.2 用户痛点

| 痛点 | 现状 | OutboundEye 方案 |
|------|------|-----------------|
| 买家发现效率低 | 展会/阿里/LinkedIn 大海捞针 | AI 每日精准推送匹配买家 |
| 海外市场盲区 | 不知道谁在买、出价多少、竞争力如何 | 全量市场分析 + 竞品动态监控 |
| 品牌可见度不可控 | 投钱做社媒/官网，AI 搜索结果看不到 | GEO 可见度日报追踪 |
| 竞品动态滞后 | 对手的新客户/新渠道 3 个月后才知道 | 实时竞品社媒变化警报 |

### 1.3 目标用户

- **Primary**: 中国外贸企业（钢构/储能/家具/机械等 B2B 行业）
- **Secondary**: 外贸独立站运营、出海品牌负责人、跨境贸易创业者

## 2. 核心功能模块（MVP）

### 2.1 必须实现（Phase 1）

#### F-01: 用户注册与账号管理

- 邮箱注册 + Google OAuth
- 企业信息填写（公司名/主营产品/目标市场）
- 个人信息保护声明
- 基础权限管理（管理员/成员）

#### F-02: 每日情报推送

- **数据源**: 海关数据 / 招标公告 / B2B 平台 / 社媒信号
- **匹配引擎**: 基于用户产品画像 → 多数据源匹配 → 排序 → 推送
- **推送形式**:
  - 邮件日报（摘要 + 详情链接）
  - Telegram Bot 实时推送（MVP 核心渠道）
  - Web 端每日看板
- **每条情报包含**: 买家名称/采购产品/预估量级/联系线索/来源/匹配度评分

#### F-03: GEO 可见度日报

- 每日扫描目标市场 AI 搜索引擎（Google AI Overviews、ChatGPT、Perplexity、Gemini）
- 跟踪关键词: 品牌名 / 核心产品关键词 / 竞品名
- 报告内容:
  - 品牌出现次数 & 趋势曲线
  - 竞品出现次数对比
  - 搜索结果的来源分析（官网/社媒/第三方平台）
  - 建议优化项
- 每周趋势对比

#### F-04: 竞品动态监控

- 监控竞品社媒变化（LinkedIn 内容/领英人员变动/官网更新）
- 监控竞品新客户获取信号
- 警报规则: 可配置 "当竞品在目标市场出现新客户时推送"

---

### 2.2 下一步实现（Phase 2）

#### F-05: 买家搜索

- 自主搜索功能（按产品/HS Code/国家/采购量）
- 搜索结果筛选（采购时间/采购频率/采购量级）
- 买家深度画像展示

#### F-06: 内容工场

- AI 自动生成目标市场开发信
- 社媒内容建议（LinkedIn 帖子/博客文章）
- 产品描述优化（适配目标市场文化/语言习惯）

---

### 2.3 远期规划（Phase 3）

#### F-07: 冷启动器

- 目标市场进入策略生成
- 渠道策略建议（社媒/B2B平台/展会/代理）
- 投放预算测算模型

#### F-08: 全链路分析

- 从"买家发现 → 第一次接触 → 询盘 → 报价 → 成交"全链路追踪
- 转化漏斗分析
- 各环节时间/成本/效率分析

## 3. 技术选型建议

### 3.1 架构选择

```
用户层  ─▶  Web (React/PWA) ─▶  API ─▶ 后台服务
                 │                          │
                 └──── Telegram Bot ────────┘
```

**推荐: Telegram Bot 优先 + Web 轻量版并行**

原因:
- Telegram Bot 开发成本低、上线快
- 推送天然适合消息渠道
- Web 版作为信息看板和深度分析入口

### 3.2 后端

| 组件 | 推荐 | 理由 |
|------|------|------|
| 框架 | Python FastAPI | 异步支持好，开发效率高，与已有系统兼容 |
| 数据库 | PostgreSQL | 结构化情报数据，扩展性好 |
| 缓存 | Redis | 推送队列 / 任务调度 |
| 任务队列 | Celery + Redis | 数据采集、GEO 扫描等后台任务 |
| AI 能力 | LLM API (deepseek/Qwen) | 情报匹配、内容生成 |

### 3.3 数据采集

| 数据源 | 采集方式 | 优先级 |
|--------|---------|--------|
| 海关数据 | API / 爬虫 | P0 |
| 招标公告 | RSS / 爬虫 | P0 |
| Linkedin | API / 爬虫 | P1 |
| B2B 平台 | 爬虫 | P1 |
| AI 搜索结果 | 自动化搜索 + 结果解析 | P0 |

### 3.4 前端

| 组件 | 推荐 | 理由 |
|------|------|------|
| 框架 | React (Vite) 或纯静态 | MVP 可纯模板 + JS 轻量版 |
| UI | Tailwind CSS + shadcn/ui | 快速出界面 |
| 部署 | 静态部署 (Vercel/Cloudflare) | 低成本 |

### 3.5 推送渠道

| 渠道 | 用途 | MVP? |
|------|------|------|
| Telegram Bot | 实时推送 | ✅ 核心 |
| Email | 日报摘要 | ✅ |
| Web 看板 | 深度分析 | ✅ 轻量版 |
| 飞书/企业微信 | 可选扩展 | ❌ Phase 2 |

## 4. 信息架构（MVP 页面）

```
/login              — 登录/注册
/dashboard          — 每日看板（情报摘要 + GEO 概况）
/intelligence       — 情报列表（完整情报流）
/intelligence/:id   — 情报详情
/geo                — GEO 可见度日报
/geo/trend          — GEO 趋势分析
/competitors        — 竞品监控
/competitors/:id    — 竞品详情
/settings           — 产品画像设置 / 推送偏好 / 团队管理
```

## 5. 非功能性需求

### 5.1 数据安全

- 用户企业信息加密存储
- 情报数据隔离（用户 A 看不到 B 的情报）
- 合规: 遵守数据采集网站的 robots.txt 和 ToS

### 5.2 性能

- 情报推送到达时间 < 5 min（数据采集后）
- 看板页面加载 < 2s
- 每日情报处理能力 > 10 万条

### 5.3 可扩展性

- 模块化架构，支持新增数据源插件
- 推送渠道可插拔
