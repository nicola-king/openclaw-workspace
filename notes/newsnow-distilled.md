## 一、项目画像

**NewsNow** 是一个优雅的实时热门新闻聚合器。核心定位：让你优雅地阅读实时热点新闻。

### 技术栈
| 层 | 技术 |
|---|------|
| 前端 | Vue/Nuxt（H3 服务端） |
| 数据库 | Cloudflare D1（边缘 SQLite） |
| 部署 | Cloudflare Pages / Vercel / Docker |
| 缓存 | 内置缓存层（默认 30 分钟） |
| 状态管理 | UnJS 生态（H3/Nitro/DB0） |

### 架构
```
shared/sources/    ← 数据源定义（类型完备，结构清晰）
server/sources/    ← 服务端抓取逻辑
shared/            ← 共享类型和工具
```

## 三、精华吸收

### 🟢 精华 1：MCP Server 直接可用

NewsNow 支持 MCP（Model Context Protocol），一个 npx 命令就能让 AI Agent 直接调取实时新闻：

```
npx -y newsnow-mcp-server
```

这意味着**任何支持 MCP 的 Agent 都能直接获取实时热门新闻**，不需要自己写爬虫。

**太一吸收**：
- 我们的情报晚报（晨间简报/晚间简报）当前使用 shared-search 手动搜索新闻
- 接入 NewsNow MCP Server → 直接获取结构化实时新闻 → 省去搜索步骤
- MCP 协议 → 如果将来支持更多 MCP 工具，这是基础设施

**动作**：
```python
# 在情报管道中加入 MCP 调用
# 通过 npx 调用 newsnow-mcp-server 获取实时新闻
# 替代手动 web_search 新闻的步骤
```

### 🟢 精华 2：自适应抓取调度

> "根据内容源更新频率动态调整抓取间隔（最快每 2 分钟），避免频繁抓取导致 IP 被封禁"

**太一吸收**：
- 我们的穿透式搜索和情报抓取没有做「自适应间隔」
- 可以借鉴这个模式：根据源的历史更新频率，动态调整抓取间隔
- 写入搜索 Agent 的调度逻辑

### 🟢 精华 3：干净的源管理架构

> "项目类型完备，结构简单，请自行探索"

`shared/sources` 目录用类型定义管理所有新闻源，结构清晰，易于扩展。

**太一吸收**：
- 我们在跨境贸易 Agent 的 intelligence-hub 中也有多个信息源
- 可以借鉴这种「类型定义+源管理」的模式，统一管理所有信息源

## 四、糟粕与局限

### 🔴 局限 1：DEMO 版，功能不完整

> "当前版本为 DEMO，仅支持中文。正式版将提供更好的定制化功能和英文内容支持。"

- 目前只有中文新闻源
- 正式版未发布
- 功能仍在开发中

**太一评估**：虽然是 DEMO，但 MCP Server 已经可以工作，不影响核心价值吸收。

### 🔴 局限 2：前端 UI 对我们无用

- 我们不需要网页阅读界面
- Telegram 就是我们的阅读终端
- 部署整个 NewsNow 只为了后端不划算

**太一评估**：只需要 MCP Server 部分，不需要部署全栈应用。

### 🔴 局限 3：单一维护者风险

- 个人项目，无公司背书
- 如果维护者不再更新，MCP Server 可能失效

**太一评估**：MIT 协议，如果 MCP Server 下线，我们可以 fork 后自建。

## 五、融入太一系统的具体动作

| # | 动作 | 价值 | 优先级 | 说明 |
|---|------|:----:|:------:|------|
| 1 | **情报晚报接 MCP Server** | 🟢 直接获新闻 | **P1** | 在 cron 晨间简报/晚报管道中加入 MCP 调用，替代手动搜索 |
| 2 | 自适应抓取调度 | 🟡 防 ban | P3 | 借鉴模式，写入搜索 Agent |
| 3 | 源管理模式 | 🟡 结构化 | P3 | 参考 shared/sources 类型定义 |

### P1 实施：情报晚报 MCP 集成

```
情报晚报 cron 触发
    │
    ├─ npx -y newsnow-mcp-server → 获取实时热门新闻
    ├─ TokenJuice 压缩 → 减少 tokens
    ├─ 太一过滤+编排 → 生成晚报
    └─ 推送 Telegram
```

**对比当前流程**：
```
当前：web_search（DDG/Bing）→ 每条手动搜 → 拼凑 → 编报
MCP：npx newsnow-mcp-server → 结构化数据 → 直接编报
```

节省：每次晚报省 5-10 次 web_search 调用，约 50-100 tokens/次。
