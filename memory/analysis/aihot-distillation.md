# AI HOT 蒸馏分析 · 对太一产品的启发

> 分析对象：aihot.virxact.com（中文 AI 资讯精选平台）
> 分析时间：2026-05-08

---

## 一、AI HOT 是什么

中文 AI 资讯精选平台。每天从数十个信源（OpenAI/Anthropic 官方、X、博客、论文）抓取 AI 动态，按 5 个版块精编成日报，08:00 自动出刊。
覆盖模型发布、产品更新、行业动态、论文研究、技巧观点五类。

**核心竞争力**：信息量密度高 vs 信息噪音低。一个创业者每天花 5 分钟看 AI HOT 日报，就能跟上行业节奏。

## 二、可供借鉴的架构模式

### 2.1 三层路由：精选 / 日报 / 全量

```
用户说"今天 AI 圈"     → mode=selected（精选池，默认）
用户说"日报"            → /api/public/daily（编辑成品）
用户说"全部/完整"       → mode=all（全量池，含次要）
```

**这个路由设计非常聪明**——99% 的用户只需要精选，3 个入口覆盖所有场景，避免了一锅端。

**对我们产品的启发**：

**买家情报平台**（跨境贸易 v11）
```
用户说"今天有什么项目"     → 精选（活跃高优项目，默认）
用户说"中东项目雷达"       → 日报式聚合报告
用户说"全部采购机会"        → 全量（含冷线索）
```
  → 当前 buyer-intel 只有 search/projects/leads 三个命令，缺少"精选→日报→全量"的**渐进式信息密度**设计

**旅游探路者**
```
用户说"成都推荐"           → 精选（必去景点+必吃餐厅，默认）
用户说"成都攻略"           → 日报式完整行程
用户说"成都全部景点"       → 全量
```
  → 当前 travel agent 只有 short/deep 两个模式，缺少"精选兜底"层

### 2.2 语义级路由：关键词 + 时间窗 + 分类多维交叉

AI HOT 的 API 支持 `q`（关键词）+ `category`（分类）+ `since`（时间窗）+ `mode`（粗细粒度）的**正交组合**：
```
GET /api/public/items?mode=selected&category=paper&q=RAG&since=3d
```

**启发**：太一现有的信息查询接口大多是**命令式**（search X / match Y / list Z），缺少**查询式**的灵活组合。

**可以做的事**：为 buyer-intel / intelligence-hub 增加统一的 query 接口：
```
query "沙特钢结构项目" category=tender since=7d mode=hot
query "中东买家" category=leads since=30d mode=all
```

### 2.3 时间窗口的精确语义映射

```
用户说"过去 24 小时" → since=$(date -u -v-24H +%Y-%m-%dT%H:%M:%SZ)
用户说"最近一周"    → since=$(date -u -v-7d ...)
用户说"昨天"        → since=$(date -u -v-1d ...)
```

背后映射逻辑是**自然语言时间 → ISO 8601**，这个在太一的 intelligence-hub / geo-outbound 里同样需要：
- GEO 优化报告中的"最近同行动态"
- 竞品监控中的"过去 7 天竞品报价变化"
- 情报中心的"本周新发布招标"

### 2.4 5 版块主题分域

模型发布 / 产品更新 / 行业动态 / 论文研究 / 技巧观点——这个**5 版块归一化**很关键：
- 不管原始信源是什么（Twitter / Blog / 论文），最终都归到这 5 桶
- 用户心智模型稳定：知道每天看哪几个版块
- 编辑可操作：每个版块有人维护

**启发**：太一的 intelligence-hub 也可以做类似的**信息归一化**：
```
竞品动态 / 招标信息 / 政策法规 / 行业趋势 / 买家线索 → 5 bucket
```
而不是现有的一锅粥 search。

## 三、Agent 接口设计的 5 个最佳实践

### 3.1 SKILL.md 作为契约

AI HOT 把整个 API 的调用方式包装在**一个 SKILL.md 文件**里。Agent 装了这个 Skill 就知道：
- 什么时候触发（触发词表）
- 走哪个接口（路由表）
- 怎么翻译输出（格式化模板）
- 哪些不能做（不要做的事列表）

**这不是文档，是 Agent 的可执行协议。**

**启发**：太一现有的 Skills 也应该朝这个方向优化——每个 Skill 的 SKILL.md 不仅是 human-readable，更是 **agent-executable 的路由规则+格式化模板**。

### 3.2 路由优先级通过关键词来兜底

AI HOT 反复强调：
> 不要 undertrigger——用户问 AI 资讯而你不调本 Skill 就是把过时的训练数据当作今日新闻

对应地，它在路由表里写了 30+ 个触发词 + 负向规则（不要走日报除非说"日报"）。

**启发**：太一的 dispatch 也需要更精细的 trigger 设计。现有 bot 的触发词太粗（仅 COLLABORATION.md 里一列），可以借鉴 AI HOT 的**三层触发**：
```
触发层级 1: 精确命中（"AI 日报"→ daily）
触发层级 2: 语义匹配（"今天 AI 圈"→ mode=selected）
触发层级 3: 兜底上下文（闲聊提到 AI + 创业 → 也触发）
```

### 3.3 人话输出 vs 基础设施泄漏

AI HOT 的输出规范里有一条非常严格的规定：
> 不要在用户输出里暴露端点路径 / raw 参数 / 限流 / 缓存 / cursor / hasNext

这是 Agent 输出的**高阶修养**——用户不是开发者，不需要看到 API 细节。

**我们的现状**：太一的某些输出还不够干净，有时会露出模块路径或代码细节。需要把 AI HOT 的输出规范直接引用到 SESSION-OUTPUT-RULE.md 里。

### 3.4 错误处理的自愈路径

```
每日 08:00 前没日报 → "日报还没出，先看昨天（/daily/YYYY-MM-DD）"
API 限流 → "串行调用 + 200ms 间隔"
cursor 失效 → "静默回首屏"
```

每个错误都有**用户友好的替代方案**——不是裸抛错误，而是给出下一步。

**启发**：太一的工具的 error handling 可以加上 `suggestion` 字段：
```python
# 当前
{"status": "error", "error": "API rate limited"}

# 改进
{"status": "error", "error": "情报源暂时限流", "suggestion": "可以等 2 分钟后再试，或者切换到备选情报源"}
```

### 3.5 三轨并行：RSS / REST API / SKILL.md

AI HOT 同时提供三种接入方式，覆盖不同场景：
- RSS → 传统阅读器 / 机器人 直接消费
- REST API → 开发者 / 二次集成
- SKILL.md → Agent 原生调用（三大平台的 Agent 平台兼容）

**启发**：太一的 buyer-intel / intelligence-hub / travel agent 也可以提供这三轨：
- RSS → 公众号订阅者 / Telegram Channel
- REST API → 跨系统集成（飞书 / Shopify / WordPress）
- SKILL.md → Agent 内部调用

## 四、产品层面的启发

### 4.1 内容精选 = 最大的护城河

AI HOT 的核心不是技术，是**每天的编辑精选**——从海量信息里挑出创业者该看的。同样的信息源谁都能抓到，但精选能力不可复制。

**我们的买家情报平台**同理：工厂付钱买的不是数据本身（数据谁都能爬到），是太一筛选过的**高价值买家线索**。精选能力 = 定价权。

### 4.2 无认证匿名访问降低门槛

AI HOT 全部 API 匿名开放，无需 token。这看起来傻，但战略对：
- 降低接入成本（零配置）
- 获取更多用户使用数据
- 建立品牌习惯
- 限流 600r/min 足够防滥用

**对我们的 buyer-intel 启示**：免费层可以更大方（不限于 3 条/月），让更多工厂试用到上瘾，再引导付费。

### 4.3 日报 = 高频触达的钩子

每天 08:00 自动出一期日报——1 天 1 次，不多不少。用户每天早上打开 AI HOT 变成习惯。

**对太一的 GEO 优化报告 / 竞品日报的启示**：定时推送的**节奏感**比内容本身更重要。固定 08:00 出、固定格式、固定长度——用户形成预期。

### 4.4 5 个版块 → 5 个微产品

每个版块都可以独立成一个产品：
- 模型发布日历（哪天发了什么模型）
- 产品更新追踪（哪家上线了什么功能）
- 行业周报（每周趋势总结）
- 论文速递（AI 论文 1 句话摘要）
- 观点聚合（大 V 在说什么）

**启发**：太一的 intelligence-hub 也可以拆出 5 个微产品——每个对应一个付费点或一个订阅层。

## 五、直接可以"拿来"的 5 个模式

| 模式 | AI HOT 做法 | 太一哪里能用 | 落地优先级 |
|------|-----------|------------|-----------|
| 精选 / 日报 / 全量 三层路由 | 按用户意图自动选粒度 | buyer-intel / travel / intelligence | P0 |
| 分类 + 时间窗 + 关键词 正交组合 | 灵活查询接口 | intelligence-hub / geo-outbound | P0 |
| 人话输出规范 | 不暴露基础设施细节 | 所有 Bot 输出 | P1 |
| 三轨接入 (RSS/API/Skill) | 降低接入门槛 | buyer-intel 付费产品 | P1 |
| 5 版块归一化 | 稳定用户心智模型 | intelligence-hub 信息归类 | P1 |

---

## 六、一句话总结

**AI HOT 最值得学的地方不是技术（API 很普通），是产品思维：**
- 精选大于全量
- 接口即契约
- 用户看到的是信息，不是调用细节
- 3 条路让人用（RSS/API/Skill）
- 每天固定节奏输出

这些原则直接可以落地到太一的 buyer-intel（买家情报平台）、intelligence-hub（情报中心）、travel agent（旅游推送）三个产品上。
