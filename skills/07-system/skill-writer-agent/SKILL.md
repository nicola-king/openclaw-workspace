## 🎯 核心理念

**Skill-Writer 不是写业务，而是写 Skill 的标准流程**

它把 Skill 创建和更新拆成一套**可重复、可审计、可验证**的工程流程：
- 先确定路径
- 再做来源合成和深度门控
- 然后进入编写、描述优化、评估与注册验证

**目标**: 不是"尽快写完"，而是让 Skill 本身具备**稳定性和来源依据**

---

## 📋 七步工作流

### STEP 1: 目标与路径解析

- 先判断是 create/update/synthesize 还是 iterate
- 再归类 Skill 类型，并只加载必要路径
- 避免无谓扩展

### STEP 2: 合成 (Synthesis)

- 多源收集、来源分级、覆盖扩展
- 决策记录与深度门控
- 是整个体系里最重的一层

### STEP 3: 迭代 (Iteration)

- 如果已有正负样本或结果反馈，就先重放工作集与留出集
- 再把行为差异带回编写阶段

### STEP 4: 编写与更新

- 以祈使语态写 SKILL.md
- 把 supporting files 控制在必要范围内
- 坚持相对路径和可移植性

### STEP 5: 描述优化

- description 既是说明，也是触发器
- 必须用真实触发短语去控制 should-trigger 和 should-not-trigger

### STEP 6: 评估 (Evaluation)

- 默认做轻量质性评估
- 高风险或用户明确要求时，再进入更深的定量基线对比

### STEP 7: 注册与验证

- **不是把文件写完就结束**
- 而是要进入规范位置，并接受快速验证与深度门控

### 方式 3: API 调用


## 🔒 Depth Gates (深度门控)

**没有通过覆盖度、来源和参考文件要求，就不允许进入下一阶段**

| 门控 | 检查项 | 状态 |
|------|--------|------|
| **来源覆盖** | ≥3 个独立来源 | ✅ |
| **参考文件** | ≥2 个参考文档 | ✅ |
| **测试覆盖** | ≥80% 核心功能 | ✅ |
| **文档完整** | SKILL.md + README | ✅ |

## 🎨 设计哲学

### 自由度匹配

根据任务脆弱性决定约束强度：
- **高风险任务** 要精确步骤
- **低风险任务** 只保留目标和边界

### 渐进式加载

- 先靠 metadata 触发
- 再加载 SKILL.md
- 最后按决策表按需读取 references
- 避免上下文浪费

### 工作流模式库

顺序、条件、反馈循环、Plan-Validate-Execute 都被整理成可复用结构

### 输出模式标准化

模板、示例、决策表和结构化数据模式，保证下游工具可以稳定消费 Skill 输出
