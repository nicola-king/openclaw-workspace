# Clash Watchdog v2.0 升级报告

> **升级时间**: 2026-04-22 01:15  
> **版本**: v1.0 → v2.0  
> **核心优化**: 智能抑制 + 自愈冷却 + 精简检查

---

## ⚠️ v1.0 问题分析

| 问题 | 说明 | 影响 |
|------|------|------|
| **检查频率过高** | 每 5 分钟检查一次 | 频繁触发 |
| **无告警抑制** | 每次发现问题就告警 | 频繁打扰用户 |
| **无自愈冷却** | 可能反复重启 | 服务不稳定 |
| **检查项过多** | 4 项检查 (进程/端口/API/代理) | 误报率高 |
| **代理检查依赖外网** | Telegram API 可能临时失败 | 误判为 Clash 故障 |

---

## ✅ v2.0 优化方案

### 1. 告警抑制机制

```bash
# 连续失败 3 次才告警
MAX_FAILURES_BEFORE_ALERT=3

# 之前：发现问题→立即告警
# 现在：问题→计数→连续 3 次→告警
```

**效果**: 避免临时故障导致的误报

---

### 2. 自愈冷却机制

```bash
# 1 小时内最多自愈 1 次
SELF_HEAL_COOLDOWN=3600  # 秒

# 之前：每次告警都尝试自愈
# 现在：告警→检查冷却期→冷却期内仅告警不自愈
```

**效果**: 避免反复重启导致的服务不稳定

---

### 3. 精简检查项

| 检查项 | v1.0 | v2.0 | 说明 |
|--------|------|------|------|
| **进程检查** | ✅ | ✅ 核心 | 必须 |
| **端口检查** | ✅ | ✅ 核心 | 必须 |
| **API 检查** | ✅ | ℹ️ 仅记录 | 不触发告警 |
| **代理检查** | ✅ | ❌ 移除 | 避免误报 |

**核心逻辑**: 只检查进程和端口，这两项失败才是真正故障

---

### 4. 状态持久化

```bash
# 状态文件：/tmp/clash-watchdog-state.json
{
  "consecutive_failures": 0,      # 连续失败次数
  "last_success_time": 1234567890, # 上次成功时间
  "last_self_heal_time": 1234567890 # 上次自愈时间
}
```

**效果**: 跨检查周期追踪状态

## 🎯 核心改进

### 之前 (v1.0)

```
每次检查 → 4 项检查 → 任意失败 → 立即告警 → 立即自愈
结果：频繁告警，频繁重启，用户困扰
```

### 现在 (v2.0)

```
每次检查 → 2 项核心检查 → 失败计数 → 连续 3 次 → 告警
                                           ↓
                                    检查冷却期
                                           ↓
                                   冷却期外→自愈
                                   冷却期内→仅告警
结果：极少告警，智能自愈，用户安心
```

---

## 💡 设计哲学

> **"宁可漏报，不可误报"**

临时网络波动是常态，Clash 真正故障是少数。  
v2.0 通过**告警抑制**和**自愈冷却**，大幅减少误报，同时保证真正故障时能响应。

> **"简约至上"**

移除代理连通性检查，因为：
- 依赖外网，容易误报
- 进程和端口正常，Clash 就基本正常
- API 检查作为参考，不触发告警
