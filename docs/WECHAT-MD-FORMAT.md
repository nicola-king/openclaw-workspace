# 微信友好的 Markdown 文件格式规范

> **版本**: 1.0.0  
> **创建时间**: 2026-04-18  
> **适用范围**: 所有需要发送到微信的 Markdown 文件

---

## 📋 核心要求

### 1. 必须包含 Front Matter (YAML 头部)

微信需要 YAML 头部来识别文档元数据：

```yaml
---
title: 文档标题
author: 太一 AGI
date: 2026-04-18
type: report | skill | doc | note
tags: ['标签 1', '标签 2']
---
```

### 2. 使用简洁的标题层级

```markdown
# 一级标题 (文档标题)
## 二级标题 (主要章节)
### 三级标题 (子章节)
```

### 3. 避免复杂格式

**✅ 推荐**:
- 简洁的列表
- 简单的表格
- 短代码块

**❌ 避免**:
- 嵌套过深的列表 (>3 层)
- 过宽的表格 (>80 字符)
- 长代码块 (>20 行)

### 4. 使用 Emoji 增强可读性

```markdown
✅ 完成  ❌ 失败  ⚠️ 警告  📊 数据  🔍 检查
```

## 📄 标准模板

### 报告类文档

```yaml
---
title: 报告标题
author: 太一 AGI
date: 2026-04-18
type: report
tags: ['报告', '分类']
---

# 📊 报告标题

> **时间**: 2026-04-18  
> **状态**: ✅ 完成

---

## 🎯 核心摘要

简洁的摘要内容

---

## 📋 详细内容

### 小标题

内容...

---

*太一 AGI · 2026-04-18*
```

### Skill 文档

```yaml
---
name: skill-name
version: 1.0.0
description: 技能描述
category: 分类
tags: ['标签 1', '标签 2']
author: 太一 AGI
created: 2026-04-18
status: active
---

# 🎯 技能名称

> **状态**: ✅ 活跃 | **版本**: 1.0.0

---

## 功能说明

...

---

*版本：1.0.0 | 创建时间：2026-04-18*
```

---

## 🔧 文件编码

- **编码**: UTF-8 (无 BOM)
- **换行**: Unix (LF)
- **最大长度**: 建议 < 500 行 (微信预览限制)

---

## 📱 微信预览优化

### 标题长度
- 一级标题：< 30 字符
- 二级标题：< 20 字符

### 表格优化
```markdown
| 项目 | 状态 | 说明 |
|------|------|------|
| 短内容 | ✅ | 简洁描述 |
```

### 代码块优化
```markdown
简短的代码示例
```
