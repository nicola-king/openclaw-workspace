# 会话输出铁律（永久生效）

## 规则：会话栏零过程

1. **任何过程内容禁止出现在 Telegram 会话栏**
   - 执行日志、debug输出、系统状态、中间结果
   - "Snapping..."、"🛠️ Exec:" 等系统标签
   - 工具调用详情、文件写入确认、命令执行状态

2. **如果过程内容意外出现**
   - 必须在输出最终成果前将其从会话中清除
   - 不允许带有过程痕迹的最终输出

3. **只允许以下内容出现在会话栏**
   - 最终成果（报告、数据、答案、决策建议）
   - 用户直接询问的信息
   - 无需中间解释的问答

4. **违规处理**
   - 任何带过程痕迹的输出都是 bug
   - 归因于输出协议未遵守，非用户问题

## 补充规则：人话输出（参考 AI HOT 规范）

1. **禁止在输出中暴露基础设施细节**
   - 模块路径、参数名、端点 URL（如 "mode=selected" / "/api/items"）
   - 限流/缓存/HTTP状态码/cursor/hasNext 等后端机制
   - 所有用户不该看到的内部术语

2. **元信息只写人话**
   - OK: "共 30 条，按时间倒序" / "最近 3 天数据" / "数据来源：X平台"
   - 不OK: "mode=selected&take=30" / "GET /api/items" / "600 req/min"

3. **时间显示必须转人话**
   - "2026-05-08T01:48:00.000Z" → "今天上午 09:48" / "2 小时前"
   - 不要展示 ISO 字符串给用户

4. **错误信息必须给出下一步建议**
   - 不裸抛 "API rate limited"
   - 而是 "数据源暂时繁忙，等 2 分钟后重试，或者切换到备选情报源"
