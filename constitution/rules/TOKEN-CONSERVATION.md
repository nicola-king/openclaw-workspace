# Token 节约原则

> **来源**: sqz 蒸馏 | **融合时间**: 2026-05-18
> **定位**: Tier 1 常驻激活
> **核心**: 每消耗一个 token 都问：这个必须让大模型做吗？

---

## 核心原则

**在保证系统正常运行的前提下，每消耗一个 token 都要自问：这个必须让大模型做吗？**

能用本地代码/脚本/CLI/缓存/索引/日志完成的，坚决本地化执行。
只有必须用大模型推理/生成/判断/总结时，才消耗 token。

## 五条具体约束

### 1. 本地优先
- 文件读写、搜索、系统命令 → 本地执行，零 token
- 网络请求（curl / web_fetch）→ 本地执行
- 脚本化、规则化的操作 → 本地执行
- 只有推理/生成/判断/总结才调模型

### 2. 去重加载
- 同一文件不重复读入上下文
- 缓存后只引用不重传
- 文件已加载 → 用行号引用，不再传完整内容

### 3. 只给必要片段
- 需要哪个函数就给哪个函数，不传完整文件
- 只提供修改相关的上下文，不传无关模块
- 大文件用 offset/limit 分段读取

### 4. 上下文压缩
- 长输出只保留结论和关键数据，省略中间过程
- 日志/执行结果 → 只传最后 N 行，不传全部
- 过滤 ANSI 颜色代码、进度条、时间戳前缀（RTK 协议）

### 5. 批量聚合
- 多条 LLM 调用合并为一次批量请求
- 同类任务一次处理，不拆零散
- 减少往返次数

## 违例示例

```
❌ 传了整个 500 行文件，实际只需要改第 50 行
❌ 第二次读同一个文件时又传了完整内容
❌ 把 50 行日志全部传进上下文，只需要最后 3 行
❌ 可以 curl 获取的数据，却让模型帮忙检索
❌ 同类 JSON 解析每次单独调模型，不写脚本
```

## 执行规则

**严格模式**（生产代码/重要任务）：全量执行 5 条约束
**宽松模式**（概念验证/快速原型）：保留 1+4（本地优先+上下文压缩），其他可放宽
