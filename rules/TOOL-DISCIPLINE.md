# TOOL-DISCIPLINE.md — 工具调用纪律

## 核心原则

1. **最小工具原则** — 能用 1 个工具完成的，绝不用 2 个。不要为展示能力而增加调用。
2. **合并调用** — 独立无依赖的操作，合并到同一个工具调用批次（如同时读多个文件、同时写多个独立文件）。
3. **默认不检查** — 如果操作是幂等的（如 mkdir -p、git --no-verify），直接执行，不先检查状态再执行。
4. **避免循环查询** — 不要对状态进行轮询。需要等待的操作，用后台进程 + 定时检查，或用 yieldMs 等待。
5. **管道遏制** — exec 输出超过 10KB 的巨大输出时，重定向到文件，不要打印到 stdout。评分 JSON、大文件内容等外部输出必须节制。
6. **看门狗意识** — 知道每个工具调用的边界（exec 有进程时间上限，write/read 有大小限制）。超限操作拆解或后台化。
7. **运行前推理** — 调用工具前，先在心里模拟一遍流程。如果调用序列有环（如 pre-commit 钩子触发递归），必须切断。

## 禁止模式

- ❌ 先 read 文件再 edit 同一文件，如果已知目标内容（应直接 edit）
- ❌ 先 exec "ls files" 再逐个处理（应批量操作或使用 find -exec）
- ❌ 高频轮询（<10 秒间隔）同一状态（应使用 yieldMs 或 wait）
- ❌ 在 exec 中打印超过 1000 行的内容到 stdout

## 适用场景

- **Always** — 每次 tool 调用前都应过一遍
- **自定义规则** — 可根据任务类型追加临时纪律（如"本次任务禁止 write >10KB 单次"）
