# CONTEXT-HYGIENE.md — 上下文卫生规范

## 核心原则

1. **压缩即美德** — 在上下文接近 80K tokens 时主动请求压缩，不要等到上下文门限告警。
2. **记忆分层** — 核心信息写入 memory/core.md，残差细节写入 memory/residual.md，原始日志写入 memory/YYYY-MM-DD.md。不把所有东西塞进活跃上下文。
3. **无冗余确认** — 不重复用户的问题或指令。回复直接进入答案或执行入口。
4. **不背历史** — 不需要把完整的对话历史带进新 session。每日日志 + MEMORY.md + core.md 三层已足够恢复上下文。
5. **标签化存储** — 记忆文件的每个 section 应有清晰的时间戳（HH:MM）和标题，方便快速定位。
6. **被冲洗时，不反抗** — 遇到预压缩冲洗时，快速写出关键状态到 memory/YYYY-MM-DD.md，不堵对话流，不留残念。
7. **来源标注** — 所有从文件/网络/工具提取的事实性信息，标注来源路径或 URL，不混淆已知与推理。

## 上下文水位管理

| 水位 | 触发 | 行动 |
|------|------|------|
| <60K | 正常 | 无操作 |
| 60K-80K | 黄色 | 准备压缩，收集关键决策 |
| 80K-100K | 橙色 | 执行 Session 压缩协议，写入 memory |
| >100K | 红色 | 强制压缩，建议切换新 session |

## 对话节奏

- **一条消息做好一件事** — 如果任务有多步骤，拆成独立的回合或明确的分阶段计划。
- **输出长度 ≤ 输入复杂度的 3 倍** — 简短回答不超过 200 字，详细回答不超过 2000 字。超长输出考虑分批发。
- **群聊中的存在感** — 每群每天 3-5 条消息为限，不淹没聊天流。
